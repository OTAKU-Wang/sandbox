### [M-2] medium [security] cds-frontend/index.html
现码：
```

```
作为“密态沙箱”系统的 HTML 入口，本页没有声明任何 CSP / referrer policy，而这份边界目前完全依赖 nginx 响应头——但 `nginx.conf` 里只有 `/api/jupyter/` 这个 location 下发了 `Content-Security-Policy`，承载应用主体的 `/` 与 `= /index.html` 两个 location 只加了 `nosniff`/`X-Frame-Options`/`Referrer-Policy`，并没有 CSP。结果是主文档实际处于无脚本来源约束状态，一旦任何一处把后端返回内容拼进 DOM（XSS 落点），没有第二道纵深防御限制外联脚本与数据外带；此外 `vite dev`（:3000）直连时也不经过 nginx，安全头全部缺失。建议在 nginx server 级补一条与 jupyter location 同等的 CSP（`default-src 'self'; script-src 'self'; frame-ancestors 'self'` 等），并注意 `frame-ancestors` 无法通过 `<meta>` 生效，必须走响应头；此处 meta 方式只适合做 dev 环境的补充默认值。

### [M-15] medium [security] cds-frontend/src/components/Auth/RoleRoute.tsx

**`allowedRoles` 类型过宽，角色名写错可编译通过并在运行时静默拒绝（安全相关的类型收紧）**

`RoleLike = UserRole | string | null | undefined`，因此 `allowedRoles` 实际接受任意字符串以及 `null`/`undefined`：
- 写成 `allowedRoles={['dataProvider']}`、`['Admin']` 这类大小写/拼写错误时 TS 不会报错，而 `normalizeUserRole` 对未知值返回 `undefined`、`hasAnyRole` 也不做大小写归一，结果是 `some(...)` 恒为 `false`，整条路由对该角色永久 404 式拒绝，且没有任何告警，只能靠人工排查。

`RoleLike` 的宽松语义是给「后端回传的用户角色」兜底的，路由声明侧属于己方可控输入，建议收紧为 `readonly UserRole[]`（`UserRole` 为字面量联合，可让拼写错误在编译期暴露）；同时在开发环境对空数组/未知角色加一条断言或 `console.warn`，避免静默失配。
