## CONVENTIONS
- Ledger prose is Chinese, findings carry `path:line` anchors; every entry was re-read against code (标「实跑」 = a repro script in this directory ran on the round's `.venv-gate`).
- `queue.mjs` parses findings with `/^#{3,4} (A\d+)/` — keep that heading shape or the queue silently drops findings.
- Views are append-only snapshots: commit them with the ledger, don't restyle. `gate-logs/*.log` are whitelisted back into git by `.gitignore:48` — that exception is load-bearing; removing it destroys the round's evidence.
- Harness outputs land next to the ledger (post-mortem fix: scripts used to hardcode the previous machine's temp dir). Override with `TMP_OUT` for a dry run elsewhere.

## ANTI-PATTERNS
- Do NOT run `report-gen.mjs` / `coverage.mjs` in place here: their raw inputs (`ocr-findings.json`, `ocr scan --preview` outputs) are not in the repo, so regeneration replaces the committed 波次/覆盖 history with 缺件声明 (measured on 10-19: a 34-line destructive diff). Write to a `TMP_OUT` copy first and read RC.
- `fix-queue.md`, `ocr-review-report.md`, `gate-evidence.md` are generated — fix the ledger or the log, then regenerate; never edit the view.
- 36 of the 53 `*.py` probes still hardcode `D:/workspace/sandbox` and `_verify-edge2.bak-1945.md` is a dead copy: they are historical evidence, not runnable tooling. Re-run a finding with a fresh script instead.
- A file named `*-green*` is not evidence: `scan-gates.mjs` explicitly flags 「名字说绿、RC 非 0」 — trust the summary line and RC.
- The 2026-10-20 follow-up round never produced findings: `docs/ocr-review-2026-10-20/` is `ocr-findings.json` = `[]` (0 L) + `triage-new.md` (9 L) + `harvest.log` (5 L), and `-20-partial/` is a single empty json. Do not read them as "nothing left to find" — the scan never landed; the live ledger stays here.
