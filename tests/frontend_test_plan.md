## 1. 测试策略

### 工具链
- **单元测试**: Vitest + @testing-library/react
- **组件测试**: Vitest + React Testing Library
- **E2E测试**: Playwright (后续阶段)
- **覆盖率目标**: 核心组件 ≥80%

### 测试分层
| 层级 | 工具 | 覆盖范围 |
|------|------|----------|
| 单元测试 | Vitest | utils/, hooks/, stores/ |
| 组件测试 | RTL | pages/ + components/ |
| 集成测试 | RTL + MSW | API 调用 + 状态管理 |
| E2E测试 | Playwright | 全链路场景 |

## 2. S2-15: 前端脚手架测试用例

### TC-S15-01: 项目构建
- **前置条件**: `npm install` 完成
- **步骤**: `npm run build`
- **预期**: 构建成功，无 TypeScript 错误

### TC-S15-02: 开发服务器启动
- **步骤**: `npm run dev`
- **预期**: 服务启动，浏览器可访问

### TC-S15-03: 路由配置
- **步骤**: 访问 `/`, `/login`, `/register`, `/dashboard`
- **预期**: 各路由正确渲染对应组件

### TC-S15-04: ProtectedRoute 守卫
- **步骤**: 未登录状态访问 `/dashboard`
- **预期**: 重定向到 `/login`

### TC-S15-05: MainLayout 渲染
- **步骤**: 登录后访问任意页面
- **预期**: 侧边栏 + 顶栏 + 内容区正确布局

### TC-S15-06: authStore 状态管理
- **步骤**: 调用 `login()` → 检查 `isAuthenticated` → 调用 `logout()`
- **预期**: 状态正确切换，token 存储/清除

- **步骤**: 发送请求，检查 Authorization header
- **预期**: 自动附加 Bearer token

### TC-S15-08: API 401 处理
- **步骤**: token 过期后发送请求
- **预期**: 自动跳转登录页

### TC-S15-09: authStore 持久化恢复
- **步骤**: 登录后刷新页面
- **预期**: 认证状态自动恢复（persist middleware）

### TC-S15-10: SM2 签名 Mock
- **步骤**: mock `window.crypto.subtle`，调用签名函数
- **预期**: 返回正确的签名值（WebCrypto 需单独测试）

### TC-S15-11: Monaco Editor Mock
- **步骤**: 在 jsdom 环境渲染 CodeEditor 组件
- **预期**: Mock Editor 组件正常渲染，snapshot 匹配

## 8. 跨页面集成测试

### TC-INT-01: 全链路 Happy Path
1. 注册 → 2. 创建产品 → 3. 发布 → 4. 创建合约 → 5. 双方签名 → 6. 创建沙箱会话 → 7. 执行代码 → 8. 查看输出 → 9. 终止

### TC-INT-02: 权限隔离
- Provider 创建的产品，Buyer 只能查看不能编辑
- Buyer 的沙箱会话，Provider 不能访问

### TC-INT-03: 状态一致性
- 合约状态变更后，列表和详情页同步更新
- 沙箱会话终止后，按钮状态正确切换

### TC-INT-04: 错误处理
- 网络断开时显示友好错误
- 422 验证错误显示字段级提示
- 403 权限错误显示提示
