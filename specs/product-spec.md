# 密态沙箱系统 · 产品规格说明书（Product Spec）

> 版本：v1.1  
> 对齐标准：国家数据局《可信数据空间发展行动计划（2024-2028年）》、TC609-6-2025-01、NDI-TR-2025-02  
> 定位：面向可信数据空间互联互通场景的密态数据沙箱产品

---

## 1. 产品概述

### 1.1 产品背景

中国正全面推进数据要素市场化流通。国家数据局《可信数据空间发展行动计划（2024-2028年）》明确将**数据沙箱、使用控制、高性能密态计算、可信执行环境**列为核心技术攻关方向，目标至2028年建成100个以上可信数据空间，形成互联互通的数据流通网络。

在此背景下，数商（数据提供方）与数据购买方之间存在根本性的信任困境：
- 数商担心数据泄露、被复制、被滥用
- 买方担心数据质量无法验证、无法自主运行算法
- 双方都需要第三方可信证明

**密态沙箱系统**（Confidential Data Sandbox，CDS）是解决上述困境的核心产品，通过硬件级隔离 + 密码学控制 + 合约约束，实现**数据可用不可见、结果可出不可取、行为可审不可改**。

### 1.2 产品定位

```

│                  可信数据空间生态                          │
│                                                         │
│  数商（提供方）  ←──数字合约──→  买方（使用方）            │
│       ↓                               ↓                 │
│  数据产品封装                    算法/应用上传             │
│       ↓                               ↓                 │
│  ┌─────────────────────────────────────────┐            │
│  │          密态沙箱系统（CDS）              │            │

│  │   远程证明 · 链上存证 · 互联互通接口       │            │
│  └─────────────────────────────────────────┘            │
│       ↓                                                  │

│       ↓                                                  │

```

### 1.3 目标用户

| 角色 | 描述 | 核心诉求 |
|------|------|----------|
| **数商**（数据提供方） | 企业、政府部门、数据机构，持有数据资产并通过数据空间变现 | 数据不离域、不被复制、使用可控可追溯 |
| **数据购买方**（使用方） | 金融、医疗、政务、工业企业，需要跨方数据做分析/建模 | 算法可自主运行、结果真实可信、成本可控 |
| **数据空间运营方** | 行业/城市/企业数据空间平台建设者 | 合规、可审计、支持互联互通 |
| **监管机构** | 国家/地方数据主管部门 | 全程可追溯、合约合规、主权可控 |

## 2. 产品目标与核心价值主张

### 2.1 核心价值主张

> **"数据进、算法进、结果出——原始数据不出域，价值安全流通"**

三大安全承诺：

| 承诺 | 含义 | 技术保障 |
|------|------|----------|
| **可用不可见** | 数据在密态环境中被使用，任何人（含运维）无法直接访问原文 | TEE 硬件隔离 + 内存加密 |
| **可出不可取** | 仅符合合约约定的计算结果可离开沙箱，原始数据无法导出 | 输出控制网关 + 差分隐私脱敏 |
| **可审不可改** | 所有操作行为均被细粒度记录并链上存证，不可篡改 | 区块链存证 + 远程证明 |

### 2.2 产品目标（OKR）

**O1：成为可信数据空间互联互通场景的标准密态沙箱基础设施**
- KR1：通过TC609-6-2025-01合规认证
- KR2：支持接入≥3个异构可信数据空间（不同运营商）
- KR3：沙箱任务启动到可用≤60秒（P99）

**O2：让数商放心上架敏感数据产品**
- KR1：数据在TEE外的任何状态均保持SM4加密
- KR2：运维人员零权限访问沙箱内数据
- KR3：数据泄露事件归因溯源时间≤1小时

**O3：让买方获得与本地计算接近的使用体验**
- KR1：支持Python/SQL/R等主流计算语言
- KR2：密态计算性能损耗≤30%（相比非加密环境）
- KR3：任务提交到结果返回端到端延迟≤5分钟（典型分析任务）

### 3.2 F1：数据产品管理

**功能描述**：数商通过数据产品管理模块，将数据资产封装为沙箱可消费的标准数据产品。

**核心功能列表**：

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 数据产品注册 | 填写产品元数据（名称、类型、字段描述、行业分类、数据量级）并上传至目录 | P0 |
| 密态数据封装 | 原始数据使用SM4-GCM加密后存入安全存储，密钥由数商持有或托管至KMS | P0 |
| 数据质量预检 | 在TEE内执行脱敏预览，生成质量报告（完整率、分布统计），供买方决策 | P1 |
| 使用策略配置 | 数商定义：可用算法白名单、禁止操作（如print/export/网络访问）、最大运行时长、输出行数上限 | P0 |
| 版本管理 | 支持数据产品版本迭代，历史版本可审计查询 | P2 |
| 产品下架/回收 | 合约到期或数商主动下架后，沙箱内关联密钥吊销，历史任务结果保留存证 | P1 |

**数据产品标准元数据模型**：

```yaml
DataProduct:
  id: "dp-{uuid}"
  name: "某省企业纳税数据2023"
  category: "政务·财税"
  dataType: ["structured", "tabular"]
  schema:
    - field: "tax_id"
      type: "string"
      sensitivity: "high"  # 高敏字段，TEE内不可输出
    - field: "revenue_range"
      type: "enum"
      sensitivity: "medium"
  volumeRows: 5000000
  updateFrequency: "monthly"
  allowedOperations:
    - "aggregate"
    - "filter"
    - "statistical_model"
  forbiddenOperations:
    - "row_level_export"
    - "join_with_external"
    - "network_call"
  outputConstraints:
    maxOutputRows: 100
    requireDifferentialPrivacy: true
    epsilon: 1.0
  sandboxConfig:
    maxRuntimeSeconds: 3600
    maxMemoryGB: 16
    allowedLanguages: ["python", "sql"]
  contractRequired: true
  certifications: ["TC609-2025", "数安标志"]
```

### 3.3 F2：沙箱运行环境

**功能描述**：密态沙箱的核心计算容器，提供硬件级隔离的安全执行环境。

**沙箱类型**：

| 类型 | 适用场景 | 计算模式 | 隔离级别 |
|------|----------|----------|----------|
| **标准分析沙箱** | SQL查询、统计分析、BI可视化 | 单任务独占TEE | 进程级（Intel SGX） |
| **模型训练沙箱** | 机器学习、深度学习训练 | 批处理长任务 | VM级（AMD SEV / 国产TEE） |
| **联合计算沙箱** | 多数商数据联合分析（无需汇聚原始数据） | MPC + TEE混合 | 多节点分布式 |
| **API服务沙箱** | 买方调用数商提供的数据服务接口 | 在线推理 | 轻量进程级 |

**沙箱生命周期**：

```
[合约激活] → [密钥分发至TEE] → [数据解密入TEE内存]
     ↓
[买方算法/SQL上传并验签] → [TEE内执行] → [输出审查]
     ↓
[结果返回买方] → [任务日志存证] → [TEE销毁/密钥吊销]
```

**沙箱隔离能力要求**：

| 安全要求 | 具体描述 |
|----------|----------|
| 内存隔离 | 沙箱内存全程加密，宿主机OS/hypervisor不可读取 |
| 网络隔离 | 沙箱内禁止主动外联；数据入口仅接受密态通道；结果出口经审查网关 |
| 存储隔离 | 临时文件仅在TEE内存中，任务结束后安全擦除 |
| 运维隔离 | 运维人员无沙箱内访问权限，所有运维操作通过外部接口并记录 |
| 代码隔离 | 买方上传代码经静态扫描白名单验证后才可执行 |

### 3.4 F3：互联互通接口

**功能描述**：支持本沙箱系统接入多个异构可信数据空间，实现跨空间数据产品消费。

**互联互通场景**：

```
空间A（金融数据空间）                空间B（政务数据空间）
       │                                    │
  连接器A                              连接器B
       │                                    │
       └──────── 互联互通层 ────────────────┘
                      │
              密态沙箱系统（CDS）
              （可部署于任意空间侧）
```

**标准接口（对齐TC609 / NDI-TR-2025-02）**：

| 接口名称 | 方法 | 描述 |
|----------|------|------|
| `/sandbox/register` | POST | 向服务平台注册沙箱实例，声明能力 |
| `/sandbox/session/create` | POST | 基于已签合约创建沙箱会话，触发密钥分发 |
| `/sandbox/task/submit` | POST | 提交计算任务（代码+参数），任务进入TEE执行队列 |
| `/sandbox/task/result` | GET | 拉取经审查的计算结果 |
| `/sandbox/attest` | GET | 获取TEE远程证明报告（供对端空间验真） |
| `/sandbox/audit/log` | GET | 查询操作审计日志（需平台授权） |
| `/sandbox/contract/bind` | POST | 绑定数字合约，激活数据使用权限 |
| `/crossspace/catalog/query` | GET | 跨空间数据产品目录查询 |
| `/crossspace/identity/verify` | POST | 跨空间身份互认（SM2证书验证） |

**跨空间会话建立流程**：

```
买方（空间B）        服务平台（空间A）       密态沙箱（CDS）
    │                     │                      │
    ├──查询数据目录────────>│                      │
    │<─返回产品列表─────────┤                      │
    │                     │                      │
    ├──签订数字合约────────>│                      │
    │<─合约ID + 权限令牌────┤                      │
    │                     │                      │
    ├──创建沙箱会话────────────────────────────>│
    │                     │  验证合约有效性        │
    │                     │<─────────────────────┤
    │                     ├─分发数据密钥──────────>│
    │                     │                TEE加载数据
    │<─会话ID + 证明报告───────────────────────────┤
    │                     │                      │
    ├──提交分析任务────────────────────────────>│
    │                             TEE内执行任务   │
    │<─计算结果（经审查）──────────────────────────┤
    │                     │  存证操作日志          │
    │                     │<─────────────────────┤
```

### 3.5 F4：使用控制引擎

**功能描述**：对沙箱内所有数据操作实施实时策略控制，确保买方行为符合合约约束。

**控制维度**：

| 控制维度 | 控制内容 | 执行方式 |
|----------|----------|----------|
| **操作控制** | 允许/禁止特定API调用（如文件读写、网络调用、进程创建） | Seccomp/TEE系统调用过滤 |
| **时间控制** | 最大运行时长、访问时间窗口（如仅工作时间可用） | 任务调度器 + 定时熔断 |
| **数量控制** | 最大查询行数、最大输出数据量、最大任务次数 | 计数器 + 配额管理 |
| **字段控制** | 高敏感字段（如身份证、手机号）在TEE内自动脱敏，结果中不可出现 | 字段级策略引擎 |
| **模型控制** | 禁止模型参数/梯度输出（防止模型逆推原始数据） | 差分隐私注入 |
| **身份控制** | 仅合约指定的买方账号可创建会话，不可转让 | SM2身份验证 |

**策略执行架构**：

```
合约签署 → 策略编译器 → 策略包（加密下发至TEE）
                              ↓
              用户操作 → 策略执行引擎（TEE内）
                              ↓
              ┌──────────────────────────────┐
              │ 允许？→ 执行操作 → 记录日志   │
              │ 拒绝？→ 返回拒绝原因 → 告警   │
              └──────────────────────────────┘
```

### 3.6 F5：输出审查网关

**功能描述**：沙箱唯一输出通道，对所有离开TEE的结果进行安全审查，防止数据泄露。

**审查能力**：

| 审查项 | 描述 | 应对措施 |
|--------|------|----------|
| 原始数据检测 | 检测输出是否包含原始行级数据（字段精确匹配） | 阻断输出 + 告警 |
| 高敏感字段检测 | 正则/模型识别身份证、手机、银行卡等 | 自动脱敏 + 标注 |
| 差分隐私注入 | 对聚合统计结果叠加校准噪声（Laplace/Gaussian机制，ε由合约指定） | 噪声注入后输出 |
| 模型参数检查 | 检测输出是否为模型权重、梯度等（防止数据逆推） | 梯度裁剪 + 聚合匿名 |
| 体积限制 | 输出文件大小/行数不超过合约约定上限 | 超限阻断 |
| 格式合规 | 仅允许JSON/CSV/图表等结构化结果，禁止二进制文件输出 | 格式验证 |

### 3.7 F6：存证审计中心

**功能描述**：对沙箱全生命周期操作进行细粒度记录，并通过区块链存证，保障不可篡改。

**审计日志字段**：

```json
{
  "event_id": "evt-{uuid}",
  "timestamp": "2025-06-01T10:23:45.123Z",
  "sandbox_session_id": "sess-{uuid}",
  "contract_id": "contract-{uuid}",
  "actor": {
    "space_id": "space-gov-A",
    "org_id": "org-fintech-001",
    "user_id": "user-sm2-cert-fingerprint",
    "role": "data_buyer"
  },
  "action": "task_submit",
  "resource": {
    "product_id": "dp-xxx",
    "data_version": "v2.1"
  },
  "policy_check": {
    "result": "allow",
    "matched_rule": "rule-003-allow-aggregate"
  },
  "output": {
    "row_count": 45,
    "dp_epsilon": 1.0,

  },

**存证架构**：

- 日志生成于TEE内，TEE签名后传输至存证服务
- 存证服务验签后写入联盟链（FISCO BCOS / 国产区块链）
- 存证数据对监管方开放只读查询
- 支持日志查询回放、争议仲裁导出

### 3.8 F7：身份与密钥管理

**功能描述**：基于国密SM2的身份体系，以及与数据产品绑定的密钥生命周期管理。

**身份管理**：

| 实体 | 证书类型 | 签发机构 | 有效期 |
|------|----------|----------|--------|
| 数商机构 | SM2 X.509 机构证书 | 数据空间运营方 CA | 1年 |
| 买方机构 | SM2 X.509 机构证书 | 数据空间运营方 CA | 1年 |
| 沙箱实例 | TEE 平台证书 + 运行时证明报告 | Intel/AMD/国产硬件厂商 | 动态 |
| 跨空间互认 | 跨空间 SM2 互信证书 | 数据空间联盟根 CA | 2年 |

**密钥管理流程**：

```
数商上传数据 → SM4密钥加密数据 → 密钥托管至KMS（HSM保护）
                                         ↓
合约激活 → KMS验证合约有效性 → 向TEE内安全分发SM4密钥
                                         ↓
TEE内解密使用 → 合约到期/任务结束 → TEE销毁密钥材料
                                         ↓
数商主动吊销 → KMS吊销密钥 → 所有关联沙箱会话立即终止
```

### 3.9 F8：数字合约集成

**功能描述**：与服务平台数字合约系统对接，以合约为驱动激活/约束沙箱行为。

**合约驱动的沙箱行为映射**：

| 合约条款 | 沙箱行为 |
|----------|----------|
| 使用期限 | 超期后密钥自动吊销，会话终止 |
| 允许操作类型 | 映射为使用控制策略包 |
| 差分隐私参数ε | 输出审查网关注入对应噪声级别 |
| 允许访问用户范围 | 身份验证时限定用户列表 |
| 结果输出限制 | 行数/体积上限配置到输出网关 |
| 争议解决条款 | 存证审计日志自动保留N天供仲裁 |

**支持的合约类型**：

- **数据查询合约**：买方提交SQL查询，返回脱敏聚合结果
- **模型训练合约**：买方上传算法在数商数据上训练，仅返回模型文件（不含原始数据）
- **API服务合约**：数商在沙箱内部署推理服务，买方通过API调用
- **联合建模合约**：多个数商数据在沙箱联合计算，无一方获取其他方原始数据

### 3.10 F9：监控运维中心

**功能描述**：为运营方提供沙箱资源、性能、安全的可观测视图（运维人员不可访问沙箱内数据）。

**监控指标**：

| 指标类别 | 指标项 |
|----------|--------|
| 资源使用 | CPU利用率、内存占用（加密后大小）、存储配额消耗 |
| 任务状态 | 队列长度、运行中任务数、失败率、平均执行时长 |
| 安全事件 | 策略拒绝次数、异常操作告警、输出审查拦截次数 |
| 互联互通 | 跨空间会话数、证明报告验证成功率、跨空间延迟 |
| 合约状态 | 活跃合约数、即将到期合约、合约违约告警 |

## 4. 用户体验规格

### 4.1 数商操作流程（主流程）

```

## 8. 非结构化数据处理规格

现实数据资产中，非结构化数据（图像、文档、音视频、日志等）占比通常超过 80%。密态沙箱须对其提供与结构化数据同等级别的安全保障，同时处理其特有的隐私泄露风险（如人脸、手写签名、语音身份、合同原文等）。

### 8.1 支持的非结构化数据类型

| 类型大类 | 具体格式 | 典型行业场景 |
|----------|----------|-------------|
| **文档类** | PDF、Word、Excel、合同扫描件、政务公文 | 政务、法律、金融尽调 |
| **图像类** | JPEG/PNG 业务图片、医疗影像（DICOM）、卫星遥感图 | 医疗、保险理赔、自然资源 |
| **音频类** | 客服录音（WAV/MP3）、庭审录音、语音笔录 | 司法、金融、电信 |
| **视频类** | 监控视频、教学视频、工业质检视频 | 公安、工业、教育 |
| **半结构化** | 日志文件（JSON/XML）、埋点数据、传感器流数据 | 工业互联网、IoT |
| **多模态融合** | 带文字批注的医疗影像、带时间戳的带标注视频 | 医疗 AI、智能驾驶 |

### 8.2 非结构化数据全生命周期安全处理流程

```
数商侧（数据入沙箱前）                       沙箱内（TEE 或降级环境）
──────────────────────────                  ────────────────────────
① 格式标准化 & 元数据提取                   ④ 密态解码与特征提取
   • 转换为沙箱标准格式                          • 图像：密态推理（人脸检测→自动打码）
   • 提取文件级元数据（大小/类型/哈希）           • 文档：密态 OCR → 敏感词识别 → 遮盖
   • 原始文件 SM4-GCM 加密                       • 音频：声纹分离 → 静音替换 or 变声
                                                  • 视频：逐帧人脸模糊 + 车牌打码
② 敏感内容预标注（数商自助）
   • 声明高敏感区域（如合同金额页、病历主诉）   ⑤ 合规计算输出
   • 配置字段级保护策略                            • 买方算法在密态数据上运行
                                                  • 输出仅为特征向量/统计结果/模型权重
③ 安全入仓（加密传输 → 密态存储）
   • TLCP 加密传输                             ⑥ 输出审查（非结构化专项规则）
   • 存入沙箱加密对象存储                          • 禁止原始文件输出
   • 完整性校验（SM3 哈希）                        • 图像输出：分辨率压缩 + 水印嵌入
                                                  • 文档输出：仅摘要/关键词/分类标签
                                                  • 音视频输出：禁止，仅允许文字转录结果
```

### 8.3 各类型专项隐私保护能力

#### 8.3.1 文档类数据

| 处理能力 | 描述 | 合规依据 |
|----------|------|----------|
| 密态 OCR | 文档内容识别在 TEE 内完成，识别结果不出 TEE，仅供算法消费 | 《个人信息保护法》第 28 条 |
| 敏感实体识别（NER） | 自动识别并遮盖：姓名、身份证、手机号、银行账号、地址、企业名 | GB/T 42574-2023 个人信息去标识化 |
| 合同原文保护 | 禁止合同正文输出；仅允许输出条款摘要、合规分类标签 | 商业秘密保护 |
| 手写签名保护 | 签名区域自动检测并黑化，不参与特征提取 | — |
| 输出格式限制 | 仅允许输出：结构化抽取字段（JSON）、分类标签、相似度得分 | — |

#### 8.3.2 图像类数据

| 处理能力 | 描述 |
|----------|------|
| 人脸自动打码 | 密态人脸检测（InsightFace/RetinaFace 在 TEE 内运行）→ 打码后供算法使用 |

#### 8.3.3 音频类数据

| 处理能力 | 描述 |

## 9. 无 TEE 环境降级安全方案

### 9.1 设计动机

TEE 硬件并非所有部署环境都具备。以下场景需要降级方案：

| 场景 | 具体原因 |
|------|----------|
| **边缘/IoT 节点** | ARM Cortex-A 低端芯片无 TrustZone 或 TrustZone 未启用 |
| **老旧服务器** | Intel Xeon E5/E7 等老型号无 SGX 支持 |
| **纯国产化环境** | 鲲鹏/龙芯/海光等部分型号 TEE 能力尚未成熟 |
| **公有云限制** | 特定云厂商实例类型不支持 TEE 直通 |
| **成本敏感场景** | 中小数商无法负担 SGX 专用服务器 |
| **跨境互联互通** | 对端空间不具备 TEE 能力，需要降级协议 |

### 9.2 分级安全模型（三级信任体系）

```
┌─────────────────────────────────────────────────────────┐
│              沙箱安全等级体系（L1 → L3）                  │
│                                                         │
│  L1  TEE 沙箱（标准级）                                   │
│  ──────────────────────────────────────────────         │
│  • 硬件隔离（Intel SGX / AMD SEV / 国产 TEE）             │
│  • 远程证明（Attestation Report）                         │
│  • 内存全程加密                                           │
│  • 适用：高敏感数据（重要/核心数据分类）                    │
│                                                         │
│  L2  软件增强沙箱（降级级）                                │
│  ──────────────────────────────────────────────         │
│  • gVisor / Firecracker microVM 内核隔离                  │
│  • Linux Namespaces + Seccomp-BPF 系统调用过滤            │
│  • 强制 MPC 多方校验（弥补硬件信任根缺失）                  │
│  • 强化输出控制（更严格的 ε 差分隐私）                      │
│  • 适用：一般敏感数据；买方明确知情并接受降级               │
│                                                         │
│  L3  最小化隔离沙箱（兜底级）                              │
│  ──────────────────────────────────────────────         │
│  • 容器级隔离（Docker + AppArmor/SELinux）                │
│  • 数据全程不解密（仅同态加密上运算，限加法/乘法）           │
│  • 输出仅允许聚合统计，禁止个体级结果                       │
│  • 适用：低敏感数据；或作为联调测试环境                      │
└─────────────────────────────────────────────────────────┘
```

### 9.3 L2 软件增强沙箱详细方案

#### 9.3.1 隔离层技术栈

| 隔离层 | 技术选型 | 作用 |
|--------|----------|------|
| **虚拟机层** | Firecracker microVM（KVM 加速） | 独立内核，共享宿主机物理内存但有 EPT 保护 |
| **容器层** | gVisor（用户态内核 Go 实现） | 拦截所有 syscall，不接触宿主内核 |
| **系统调用过滤** | Seccomp-BPF（白名单模式，仅开放约 40 个必要 syscall） | 消除内核攻击面 |
| **网络隔离** | Network Namespace + iptables 规则链 | 禁止沙箱主动外联 |
| **文件系统** | OverlayFS 只读基础层 + tmpfs 可写层（任务结束自动销毁） | 无持久化存储 |
| **进程权限** | Linux Capabilities 最小化（去除 CAP_SYS_ADMIN 等 30+ 高权限）| 根权限降权 |

#### 9.3.2 补偿安全控制（弥补硬件信任根缺失）

因缺少 TEE 硬件信任根，L2 必须通过软件层面叠加补偿控制：

| 补偿控制 | 具体措施 | 目的 |
|----------|----------|------|
| **MPC 双方验证** | 数商侧和买方侧各持有数据密钥分片，计算前通过 MPC 协议协商重组（无需信任第三方计算节点） | 弥补缺少硬件信任根 |
| **差分隐私加严** | L1 默认 ε=1.0；L2 强制 ε≤0.5，高敏感数据 ε≤0.1 | 更强输出噪声保护 |
| **输出行数上限收紧** | L1 最大 100 行；L2 最大 20 行；L3 仅允许标量输出 | 降低信息泄露 |
| **代码静态扫描加严** | 除白名单 API 外，禁止所有 IO 操作；L2 额外扫描侧信道风险代码模式 | 防止隐蔽信道 |
| **运行时行为监控** | eBPF 探针全程监控沙箱内系统调用序列，异常模式触发实时熔断 | 弥补无远程证明 |
| **内存加密（软件模拟）** | 使用 LUKS/dm-crypt 对沙箱内存映射文件加密 | 降低内存 dump 风险 |
| **操作员双人审核** | L2 任务需运营方≥2人确认启动，录屏存证 | 人工补偿 |

#### 9.3.3 软件可信证明（替代远程证明）

L2 无法产生 TEE 硬件证明报告，采用软件可信证明替代：

```
① 沙箱环境镜像哈希（SM3）
   → 在部署时由数商/买方双方验证镜像完整性（供应链保障）

② 代码执行前承诺（Commitment）
   → 买方算法代码 SM3 哈希锁定，执行时验证代码未被替换

③ 运行时度量日志
   → eBPF 实时采集关键系统调用序列，生成执行轨迹摘要
   → 摘要上链，供事后审计

④ 多方背书（可选）
   → 邀请受信任第三方机构对 L2 环境配置独立审计并签发背书证书
   → 背书证书替代 TEE 证明报告附于会话记录中
```

### 9.4 合约层降级感知

降级模式须在合约层明确标注，数商对每个数据产品配置允许的最低安全等级：

```yaml
DataProduct:
  securityLevelPolicy:
    minimumLevel: "L1"        # 仅允许 TEE 沙箱（最高限制）
    # 或
    minimumLevel: "L2"        # 允许降级至软件增强沙箱
    degradeConditions:        # 仅在满足条件时允许降级
      - "buyerNodeNoCEE"      # 买方节点无 TEE 能力
      - "crossSpaceLowSens"   # 跨空间互联互通低敏感场景
    degradeRequires:
      - "buyerExplicitConsent"         # 买方明确知情同意
      - "dpEpsilonMax: 0.5"            # 差分隐私加严
      - "mpcVerificationRequired: true" # 强制 MPC 双方验证
      - "auditDoubleApproval: true"    # 双人审核启动
```

**合约签署时降级披露要求**：

买方须在合约中签署"安全等级降级知情确认书"，明确告知：
1. 本次计算环境安全等级为 L2（软件增强）/ L3（最小化）
2. 无法提供硬件级内存加密保证
3. 已通过 MPC + 差分隐私等补偿措施降低风险
4. 数商对本次降级计算结果的可信度不做 TEE 级别的保证

### 9.5 安全等级对比表

| 维度 | L1（TEE标准级） | L2（软件增强级） | L3（最小化级） |
|------|----------------|-----------------|---------------|
| 硬件信任根 | ✅ CPU 硬件 | ❌ 无 | ❌ 无 |
| 内存加密 | ✅ 硬件加密（TME/SME） | ⚠️ 软件 dm-crypt | ❌ 无 |
| 远程证明 | ✅ 标准 Attestation | ⚠️ 软件可信证明 | ❌ 无 |
| 系统调用隔离 | ✅ TEE Enclave | ✅ gVisor + Seccomp | ✅ Seccomp |
| 差分隐私 ε | ≤1.0 | ≤0.5 | ≤0.1（仅聚合） |
| 输出行数上限 | 100 行 | 20 行 | 仅标量 |
| 适用数据级别 | 重要/核心数据 | 一般敏感数据 | 低敏/公开数据 |
| 支持非结构化 | ✅ 全类型 | ⚠️ 文档/图像（限制） | ❌ 不支持 |
| 互联互通证明 | ✅ TEE 证明报告 | ⚠️ 软件背书证书 | ❌ 不可用于跨空间 |
| 合规等级 | 最高合规 | 条件合规（需披露）| 仅限内部测试 |

### 9.6 部署检测与自动降级

```
沙箱服务启动时自动探测硬件能力：

① 检测 TEE 支持：
   cpuid | grep sgx → SGX 检测
   /dev/sgx_enclave 设备存在性检测
   AMD SEV：检测 /dev/sev 设备
   国产 TEE：调用厂商 SDK probe 接口

② 根据探测结果：
   有 TEE → 启动 L1 模式，生成 Attestation Report
   无 TEE，有 KVM → 启动 L2 模式（Firecracker + gVisor）
   无 KVM → 启动 L3 模式（仅容器级隔离）
   → 将等级写入节点元数据，上报服务平台

③ 服务平台根据节点等级：
   → 仅将 L1 数据产品路由至 L1 节点
   → L2 产品允许路由至 L1 或 L2 节点
   → 跨空间互联互通仅使用 L1 节点（默认）
```
