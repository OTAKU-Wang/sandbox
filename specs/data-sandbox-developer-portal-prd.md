# 星信可信数据空间 · 数据沙箱开发平台（开发者工作台）
# 产品功能与需求规格说明书 (PRD & SRS)

> **版本**：v2.0 (生产闭环与唯 CubeSandbox 架构版)  
> **定位**：星信可信数据空间面向数据使用方、算法与模型工程师的核心交互平台  
> **运行时基准**：**唯 CubeSandbox MicroVM 硬件级隔离**（全面废弃与下线 Bubblewrap、Kubernetes 容器与模拟层）  
> **架构模式**：**双模式工作台体系**（默认：极简高效「开发者工作台」；管理态：无缝直通「空间管理后台」）  
> **交互原型**：`specs/prototype-v3.html`（对齐 `基础版数据沙箱原型/` 视觉体系）

## 1. 产品概述与核心理念

### 1.1 产品背景与目标
在星信可信数据空间（Trusted Data Space）中，数据沙箱是实现“**数据可用不可见、结果可出不可取、行为可审不可改**”的枢纽设施。
新设计的《数据沙箱开发平台》打破了以往以“底层集群运维”为中心的繁琐逻辑，以**“开发任务（Task）”**为唯一第一公民，打造专为数据使用方算法工程师设计的敏捷、沉浸式开发平台。

### 1.2 核心价值闭环
1. **统一算力底座（唯 CubeSandbox 架构）**：
   - 全面抛弃历史上的 Bubblewrap (bwrap/L0/L3) 进程沙箱与 Kubernetes Pod 容器沙箱。
   - 所有在线调试与批处理执行**100% 运行于独立的 KVM MicroVM（CubeSandbox 节点数据面直驱）**中，具备内核级硬件隔离、内存加密、私有虚拟文件系统（XFS reflink）及独立网络命名空间。
2. **端到端开发闭环**：
   - 关联已授权数据产品与合约约束。
   - 提供基于 Web IDE 的在线 Python 调试环境，调试沙箱内存隔离。
   - 调试成功后一键**“固化发布任务版本（Workload）”**。
   - 正式执行生成不可篡改运行日志与 T5 出域审查报告。
3. **成果交付三通道闭环**：
   - **离线数据集导出**：注入使用者隐形数字水印与 SM2 签名的加密结果包下载。
   - **在线 OpenAPI 导出**：自动生成对外受控查询 API，提供白名单、限流与调用监控。
   - **结果推送 Webhook**：自动化定时批处理结果的主动回调投递。
4. **全链路存证不可篡改**：
   - 操作日志与沙箱执行流水走 SM3 规范化哈希，落盘 ClickHouse 并实时锚定至星信可信链 Merkle 根。

## 2. 总体架构与系统布局

### 2.1 双模式工作台架构 (Dual-Workspace Architecture)
系统采用**双工作台模式**，彻底实现“开发者沉浸开发”与“系统管理员全栈运营”的分权解耦：

```
┌────────────────────────────────────────────────────────────────────────┐
│               顶部全局导航条（星信可信数据空间 · 数据沙箱开发平台）               │
│  [沙箱集群: 沈阳数据中心R]  [欢迎登录，张伟]  [⚙️ 切至空间管理后台 (Admin Only)] │
└────────────────────────────────────────────────────────────────────────┘
                                    │
           ┌────────────────────────┴────────────────────────┐
           ▼                                                 ▼
┌────────────────────────────────────┐    ┌────────────────────────────────────┐
│      默认：开发者工作台 (Portal)      │    │     管理态：空间管理后台 (Admin)      │
│  （面向算法工程师/数据使用方）        │    │  （面向平台管理员/合规安全官）          │
│                                    │    │                                    │
│  4+2 菜单体系：                    │    │  承载能力：                        │
│  1. 首页（平台总览）                │    │  • CubeSandbox 节点拓扑与硬件纳管   │
│  2. 我的开发（任务管理/IDE/详情）   │    │  • 平台 CA 根证书与 KMS 密钥管理    │
│  3. 我的结果集（三通道资产中心）    │    │  • 跨空间联邦连接器配置             │
│  4. 安全管理（操作日志与验真）      │    │  • MPC 分布式密钥分片（若启用）     │
│  + 开发指引文档 & 环境配额说明      │    │  • 系统全局安全策略与审计归档       │
└────────────────────────────────────┘    └────────────────────────────────────┘
```

### 2.2 唯 CubeSandbox 架构规范与历史模块下线
为保证系统的极致稳定与合规诚实，全面清理历史技术栈：
- **下线清单**：
  1. 彻底移除前端创建合约/会话时的 `L0 (Process)`、`L1 (SGX)`、`L2 (Firecracker)`、`L3 (bwrap)`、`k8s (Pod)` 等多等级选项。
  2. 彻底下线 `K8s 运营`（`/ops/deployments`、`/ops/network-policies`、`/ops/pvcs`、`/ops/logs`）。
  3. 彻底下线 `CapabilityMatrix` 历史多等级混杂对比页面。
- **CubeSandbox 规范**：
  - 开发者在界面上仅需配置直观的业务资源规格：
    - **调试环境内存配额**：2 GB ~ 32 GB（默认 8 GB）
    - **执行环境内存配额**：2 GB ~ 64 GB（默认 16 GB）
    - **执行超时限制**：默认 3600 秒
  - 底层由 Cubelet 自动调度至可用硬件计算节点，通过 gRPC 启动 MicroVM。

## 3. 业务闭环与全功能页面规格说明

平台共包含 4 个核心业务模块 + 2 个常驻指引页面，共计 18 个全流程界面（含原有原型 10 个界面及本次补齐的 8 个闭环界面）：

### 3.1 首页（平台总览）
* **定位**：开发者的日常全局看板，掌握资源、任务、接口与安全概况。
* **主要区域**：
  1. **问候卡片**：显示用户名称、所属节点、快速发起按钮（`查看开发任务`、`创建开发任务`）。
  2. **核心指标 4 宫格**：
     - `开发任务总数`：进行中数量、已结束数量。
     - `结果集导出接口`：在线数量、离线数量。
     - `今日数据调用次数`：最新调用时间戳。
     - `今日操作日志`：今日操作量、失败报警数（标记不可篡改留存）。
  3. **开发任务总览（中左）**：展示最近 5 条任务（名称、状态、调试方法、创建时间），快捷操作（`调试`、`执行`、`详情`）。
  4. **沙箱内存使用（中右）**：
     - `调试内存占用`：实时占用量 / 配额进度条（如 3.8G / 8G，标记“占用中”）。
     - `执行内存占用`：正式批处理占用量 / 配额进度条（如 0G / 16G，标记“待执行”）。
     - 提示说明：“调试内存随在线会话占用，退出环境自动释放；执行内存仅在任务跑批时独占”。
  5. **趋势图与最新结果集（底部）**：近 7 天调试与执行趋势柱状图；最新结果集表格（名称、交付通道类型、调用/下载数、状态、操作链接）。

### 3.2 我的开发模块

#### 3.2.1 任务列表页 (`2-1`)
* **筛选栏**：任务名称模糊搜索、任务状态（全部/进行中/已结束）、调试方法（Python 3.10 / SQL）、重置、查询。
* **任务卡片网格**：
  - 卡片头：图标、任务名称、系统全局唯一 ID（`TASK-YYYYMMDD-XXX`）、状态 Tag（`进行中` 绿色、`已结束` 灰色）。
  - 信息项：沙箱引擎（`CubeSandbox MicroVM`）、模型调试方法、创建时间。
  - 操作栏：`调试`（进入在线 IDE）、`执行`（触发生产任务执行弹窗）、`详情`（进入详情页）。

#### 3.2.2 新增开发任务页 (`2-2`)
* **基本信息**：任务名称（必填）、任务编号（系统自动生成，只读）、所属节点（当前节点，只读）、任务描述（多行文本）。
* **我的合约**：
  - 合约名称（必填，绑定本次任务的合规约束）。
  - 模型调试方法（下拉：Python 3.10、SQL-DuckDB）。
  - 结果导出方式（下拉三通道：OpenAPI 导出、离线数据集导出、结果推送 Webhook）。
* **资源配置**：
  - 调试环境内存(G)：步进器，2G~32G，默认 8G。
  - 执行环境内存(G)：步进器，2G~64G，默认 16G。
  - 配额建议提示条：训练任务建议调试不低于 8G，数据超 10 万行建议执行不低于 16G。
* **关联数据**：
  - Tab 切换：`本节点登记的数据产品`、`我购买的数据产品`。
  - 数据表格：勾选框、产品名称、产品类型、交付方式（TEE-离线结构化数据）、交付场景、操作（详情查看）。
  - 右侧已选数据看板：已选择数量、清空按钮、已选产品卡片与“移除”按钮。
* **提交**：底栏带有确认提示，支持“取消”与“完成并进入调试”。

#### 3.2.3 在线调试环境（Web IDE）(`2-3`)
* **顶部状态栏**：任务名称、CubeSandbox 连接状态指示灯（绿色 `● 沙箱已连接`）、自动保存状态、资源监控（CPU 占用、内存占用）。
* **操作快捷栏**：`← 返回列表`、`▶ 运行调试脚本`、`⏹ 停止运行`、`📦 固化发布版本`。
* **左侧工程目录树**：
  - `scripts/`（工程主代码区）：支持新建文件、重命名、删除。包含 `train_model.py` 等脚本。
  - `/sandbox/data`（只读数据挂载区）：展示已授权数据产品文件（如 `train_dataset.csv`），只读锁标，禁止写入。
  - 存储配额提示：展示已用容量与上限（如 128 MB / 2 GB）。
* **中间代码编辑区**：
  - 集成 Monaco Editor，支持 Python 语法高亮、自动补全、行号、缩进与括号匹配。
  - 约定数据路径变量：`DATA_DIR = "/sandbox/data"`，输出路径变量：`OUTPUT_DIR = "/sandbox/output"`。
* **底部终端与日志控制台**：
  - Tab：`输出 (Output)`、`问题 (Problems)`、`终端 (Terminal)`。
  - 日志流式回显：环境初始化、数据挂载日志、模型训练迭代输出、DLP 审查日志、耗时与退出码。

#### 3.2.4 调试代码固化发布弹窗 (`2-7` 闭环补齐)
* **业务目的**：解决原设计中调试完成后代码如何转为生产版本的缺失。
* **内容规格**：
  - 提示信息：说明代码将被提取并计算 SM3 规范化摘要，生成正式可运行 Workload。
  - 发布版本号：如 `v1.0.0`。
  - 主入口脚本：如 `scripts/train_model.py`（自动绑定）。
  - 更新说明：记录模型迭代参数与评估指标。
  - 提交后自动生成 Workload 记录，赋权进入正式批处理执行与 OpenAPI 导出。

#### 3.2.5 任务详情页 (`2-4`)
* **页面头**：任务名称、状态 Tag、唯一编号、创建时间、最近执行时间；快捷按钮（`进入调试`、`执行任务`）。
* **KPI 统计**：任务状态、调试方法、关联数据产品数、产出结果集数。
* **基本信息与合约卡片**：展示所属节点、合约名称、沙箱运行时（`CubeSandbox MicroVM`）、导出方式、资源规格。
* **关联数据卡片**：展示已授权的数据集列表及交付场景。
* **运行记录表格**：
  - 字段：执行时间、操作类型（`调试执行` / `正式执行`）、执行环境规格、状态（成功/失败/运行中）、耗时、操作（`查看日志与DLP审查`）。
* **产出结果集表格**：
  - 字段：结果集名称、生成时间、数据行数、文件大小、导出状态、操作（`查看结果集`）。

#### 3.2.6 任务执行确认与参数配置弹窗 (`2-5` 闭环补齐)
* **业务目的**：点击“执行任务”时的参数确认与生产环境调度闭环。
* **内容规格**：
  - 硬件隔离提示：告知任务将在沈阳数据中心独立的 CubeSandbox MicroVM 独占运行。
  - 执行版本选择：下拉选择已固化发布的版本（如 `v1.0.0` 或最新发布版）。
  - 资源规格确认：确认执行环境内存（16 GB）。
  - 动态运行参数：支持以 JSON 格式向脚本传入环境变量或启动参数（如超参数、批大小）。
  - 提交动作：调用后端 `POST /api/v1/compute/runs`（当前入参仅 `contract_id`；按负载选版本与传动态运行参数尚未实现，已计入 P4 运行参数面），任务状态切为 `PROVISIONING` -> `RUNNING`。

#### 3.2.7 运行记录详情与日志追踪抽屉 (`2-6` 闭环补齐)
* **业务目的**：在详情页点击“查看日志”时滑出的全景运维追踪视图。
* **内容规格**：
  - 顶部：运行编号（如 `RUN-20260812-1042`）、启动耗时、退出码。
  - 实时日志区（控制台黑底高亮）：
    - 节点调度与 MicroVM 启动日志。
    - KMS DEK 国密密钥获取与数据安全挂载日志。
    - 代码执行 STDOUT / STDERR。
  - **T5 出域脱敏与 DLP 审查专区**：
    - 敏感数据扫描判定结果（PII 检测 0 违规）。
    - 聚合行数阈值检查（实际 36 行 < 上限 10000 行）。
    - 隐形数字水印注入记录（记录水印载荷：使用者 ID + 合约 ID）。
    - SM2 输出凭证签名生成。

### 3.3 我的结果集模块

#### 3.3.1 结果集多通道资产中心 (`3-0` 闭环补齐)
* **业务目的**：补齐原原型直达 OpenAPI 的缺陷，建立统一的结果资产看板。
* **Tab 分类**：
  1. `📁 文件结果集 (离线交付包)`：
     - 展示任务在 `/sandbox/output` 产出的数据文件（如 CSV、Parquet、JSON 报告、模型权重 pkl）。
     - 字段：结果集文件名、关联任务/合约、大小、T5 审查状态（`✔ DLP 审查通过`）、数字水印状态（`已注入隐形水印`）、生成时间。
     - 操作：
       - `预览脱敏数据`：在线弹窗只读抽样预览前 10 行脱敏数据结构。
       - `下载结果包`：下载经国密 SM4 加密或打包的 Delivery Bundle（包含 MANIFEST、数据文件、SM2 签名凭证）。
  2. `🔌 OpenAPI 导出接口`：原原型的 OpenAPI 列表。
  3. `🔔 结果推送 (Webhook)`：支持查看自动化定时计算的主动推送投递记录。

#### 3.3.2 OpenAPI 导出-接口列表页 (`3-1`)
* **筛选栏**：接口名称、状态（全部/正常/异常）、是否在线（全部/上线/离线）、查询、重置。
* **表格字段**：接口名称、API ID (UUID)、接口描述、有效期、apiUrl、状态 Tag、是否在线 Tag。
* **操作栏**：`在线调试`（补齐弹窗）、`编辑`、`删除`、`接口监控`。

#### 3.3.3 OpenAPI 导出-新建 API (`3-2`)
* **表单项**：
  - 接口名称（必填）、关联任务（必选已固化版本）、接口状态 Switch（默认上线）、接口描述。
  - 接口有效期：单选（永不过期 / 指定截止日期）。
  - 安全保障：单选（IP 白名单 / 不限制），多行文本支持网段与 IP 逗号分隔。
  - 查询模式：开放查询 / 限定查询；查询范围：最新结果集 / 历史所有结果集。
  - 结果集字段定义：来自合约的结果集 Schema（字段名、类型、脱敏泛化算子）。

#### 3.3.4 OpenAPI 在线调试与鉴权说明弹窗 (`3-4` 闭环补齐)
* **业务目的**：新建或查看 API 时，开发者需要直接测试接口响应。
* **内容规格**：
  - 接口请求说明：Method (`POST`)、URL (`/open/v1/{slug}`)。
  - Header 鉴权：自动提取或生成平台 API Key (`X-CDS-API-Key: cds_live_...`)。
  - Request Body 编辑器（JSON）与一键发送测试。
  - Response Body 回显及状态码展示（200 OK，包含脱敏后的 JSON 结果）。

#### 3.3.5 OpenAPI 导出-接口监控页 (`3-3`)
* **头信息**：接口名称、状态 Tag、在线 Tag、关联任务、有效期；操作按钮（`返回列表`、`刷新数据`、`编辑接口`）。
* **指标 3 宫格**：调用总次数、最新调用时间、调用成功率（%）。
* **使用调用明细表格**：序号、调用 ID、调用时间、来源 IP、耗时、调用状态 Tag（`调用成功` / `IP不在白名单` / `限流阻断`）。

#### 3.3.6 结果推送 Webhook 配置与投递监控 (`3-5` 闭环补齐)
* **业务目的**：补齐数据空间自动化调度场景下的主动结果推送。
* **内容规格**：
  - 配置表单：接收端 URL (HTTPS)、触发事件（批处理计算完成）、签名密钥 Secret、失败退避重试次数（1~5 次）。
  - 投递历史流水表：投递时间、目标 URL、响应状态码 (200/500)、重试次数、投递状态。

### 3.4 安全管理模块

#### 3.4.1 操作日志页 (`4-1`)
* **定位**：记录平台所有高危与合规操作，数据仅可查看与导出，严禁任何角色修改或物理删除。
* **筛选栏**：操作类型（创建调试沙箱、进入生产环境、结果集导出、数据调用）、关键字（操作人/对象）、操作结果（成功/失败）、时间区间。
* **快捷标签**：全部、创建调试沙箱、进入生产环境、结果集导出、数据调用。
* **表格字段**：操作时间、操作类型 Tag、操作人、来源 IP、操作结果 Tag、不可篡改存证状态（`区块链已锚定`）、操作（`详情`）。
* **顶栏操作**：`📥 导出审计日志`、`🔄 刷新`。

#### 3.4.2 操作日志详情弹窗 (`4-2`)
* **头信息**：日志编号（`LOG-YYYYMMDD-HHMMSS-XXXX`）、生成时间、操作类型 Tag。
* **基础信息**：操作时间、操作人（张伟 · 沈阳数据中心R / 模型工程师）、来源 IP、操作结果、操作对象（CubeSandbox 执行环境 16G）。
* **操作内容**：
  - 操作类型代码（如 `EXEC_ENV_ENTER`）。
  - 环境标识（如 `env-16g-20260812-095840` · CubeSandbox 硬件级隔离环境）。
  - 关联合约名称与关联数据产品清单。
  - 操作细分耗时（环境申请 0.9s · 权限校验 0.38s）。

#### 3.4.3 区块链存证与 Merkle 验真弹窗 (`4-3` 闭环补齐)
* **业务目的**：落实“行为可审不可改”的国密存证闭环，向监管与合规方提供真实验真入口。
* **内容规格**：
  - 存证状态徽章：绿色高亮 `✅ 存证哈希校验一致 · 记录真实未篡改`。
  - 原文字节 SM3 哈希：如 `sm3:4e2c90a187b5d12ef3...7a91`。
  - Merkle 树叶子节点索引与批次号。
  - 星信可信链存证记录：Block 高度（如 `#1,842,903`）、交易哈希 TxHash、链上上链时间戳。
  - 关联审查凭证：T5 DLP 审查报告摘要哈希。

## 4. 数据字典与领域模型映射

对齐系统既有 SQLAlchemy 数据库模型，建立统一模型映射：

| 业务实体 | 原型对应字段 | 数据库模型及映射关系 | 说明 |
|---|---|---|---|
| **开发任务 (Task)** | 任务名称、编号、描述、资源规格 | `notebooks` + `workloads` 表 | 将工作负载抽象为任务实体，关联脚本版本与沙箱配置 |
| **任务固化版本** | 发布版本号 (v1.0.0)、固化哈希 | `workloads (is_latest, entrypoint_hash)` | 经测试沙箱验证通过的不可篡改执行载荷 |
| **沙箱会话** | 调试会话 / 执行会话 | `sandbox_sessions` | 唯一记录 `sandbox_level = 'l2c'` (CubeSandbox) |
| **文件结果集** | 结果文件、DLP状态、水印状态 | `delivery_bundles` | 记录交付包归属、T5 审查记录、水印元数据 |
| **OpenAPI 接口** | 接口名称、API ID、URL、白名单 | `api_endpoints` | 记录 slug、限流配额、调用计数、JSON Schema |
| **推送配置** | 接收端 URL、密钥、重试次数 | `webhook_subscriptions` | 记录自动计算成果投递订阅 |
| **推送流水** | 投递时间、状态码、响应结果 | `webhook_deliveries` | 记录逐条投递日志，解绑物理外键保障留存 |
| **操作审计日志** | 操作类型、操作人、IP、存证 | `audit_events` (PG) + ClickHouse | SM3 哈希计算与链上 Merkle 根锚定 |

## 5. 安全与错误契约 (W2 Contract)

平台所有 API 交互严格对齐 W2 统一错误契约，杜绝静默失败与模糊报错：
```json
{
  "code": "WORKLOAD_TEST_REQUIRED",
  "message": "任务尚未在调试环境中测试通过，禁止提交正式生产执行",
  "detail": {
    "task_id": "TASK-20260812-001",
    "required_step": "请先在在线 Web IDE 中点击运行并确认退出码为 0"
  },
  "request_id": "req-8f2c71a0-9b4e"
}
```

* **常见错误码矩阵**：
  - `SESSION_TERMINATED (410)`：沙箱会话已终止，客户端立即停止重试并提示用户重新创建。
  - `OUTPUT_BLOCKED (502)`：任务输出内容包含敏感身份证/手机号原文，被 T5 网关阻断。
  - `QUOTA_EXCEEDED (429)`：当前租户 CubeSandbox 内存超出分配配额。
  - `WORKLOAD_HASH_MISMATCH (412)`：代码内容被外部篡改，哈希不匹配，拒绝执行。
