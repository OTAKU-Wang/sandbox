## CONVENTIONS
- AuthN is per module, AuthZ is per mount: `get_current_user` in 24 modules, `require_roles` in 22, `get_business_user` in 13. Five modules use none of the three (`admin`, `cube_egress` service token, `health`, `metrics`, `session_stream` 30 s single-use jti ticket) — `metrics` still carries mount-time `require_group("audit")`, so "no AuthN dep" ≠ unauthenticated. Function-permission checks (`require_group`) are mounted in `main.py`, never repeated inside a handler. Authorization is NOT shared — each module defines local `_can_view_all_*` / `_can_operate_*` / `_can_manage_*` helpers.
- No module-level prefix except `admin.py`: the prefix is assigned ONCE in `main.py`. Deviations are deliberate: `health`/`metrics` at root, `open_api` under `/open/v1`, `cube_egress` under `/internal/audit` (service token + `require_human`), absolute paths for `session_stream` and `jupyter_proxy`, `admin` on a separate app.
- List envelope `{items, total, page, page_size}`; opt-in keyset cursor (W8) via `X-Next-Cursor` header (no `total` in cursor mode) — implemented in only 4 modules: `connectors`, `contracts`, `data_products`, `sandbox_sessions`.
- Every mutating endpoint calls `audit_service.log(db, action=...)`. **Denial / failure paths call `audit_service.log_standalone(...)` instead** — `get_db` rolls back the request session on exception, so a `log(db, …)` followed by `raise` loses the audit row in production (invisible under `tests/conftest.py`'s override, which neither commits nor rolls back). Measured split: 147 `log(` vs 27 `log_standalone(`; the latter appears in 9 modules only (auth, connectors, deliveries, dev_sandbox, open_api, output_control, rag, sandbox_db, sandbox_sessions). `audit.py` adds Merkle anchoring; the PG log is append-only tamper-evident, NOT the chain.
- Newer refinement worth copying (`open_api.py:96-115`): when the business effect already happened (sandbox ran, `calls_used` metered), the audit write goes in an `async with db.begin_nested()` SAVEPOINT and its failure only logs `[CRITICAL]` + falls back to `log_standalone` — the audit row must never veto the business commit.
- Errors: `HTTPException` dominates; W2 `CDSError(code=…)` where the client needs a sentinel (`RUNTIME_UNAVAILABLE`, `LEGACY_LEVEL_RETIRED`, `TEE_NODE_UNAVAILABLE`, `KMS_UNAVAILABLE`, 412 publish gate). Retryability is decided in-module (`open_api._RETRYABLE = {RATE_LIMITED, QUOTA_EXCEEDED}` → 429, else 502).
- Chinese `detail=` is per file, not per feature: `jupyter_proxy` (all its 403s), `integrity`, and the 429 `并发会话数已达上限 (5)` live in `sandbox_sessions.py`. `quota.py` raises no 429 and has zero Chinese details — the old "quota 429" note was wrong. Match the language already in the file you edit.
- Commit discipline: commit before responding (`sandbox_nodes.py:141` — a 201 must not race row visibility; `sandbox_sessions.py:570` — the session row must be committed before the provision call), and every exit path returns its own quota reservation (`:610`).
- Fail-closed intent is written into comments ("never released", "never the plaintext key", "never silent fallback") — never relax one to make a test pass.

## ANTI-PATTERNS (THIS PROJECT)
- **The route layer is not a leaf.** 7 `app/services/*` modules import `app.api.*` function-locally (`auth_service`, `compute_scheduler`, `delivery_service`, `notebook_service`, `rag_generative_service`, `session_lifecycle`, `workflow_service`). Renaming `sandbox_sessions.create_sandbox_session` / `execute_in_sandbox` / `_l2c_file_op` / `_session_dek` / `_session_workspace_or_400`, or `sandbox_nodes.detect_stale_nodes` / `recover_stale_nodes`, breaks the service layer silently.
- Role helpers are copy-pasted per module (`_can_view_all_products` is AST-identical in `data_products.py` AND `field_exposure.py`; 12 more single-module variants). Consolidating into `core/deps` is the known direction — don't add more copies.
- `sandbox_sessions.py` is the complexity sink; split before adding features there.
- `quota.MAX_ACTIVE_SESSIONS = 5` and `quota.CONCURRENT_STATUSES` are deliberate same-source copies of constants defined *inside* `create_sandbox_session` (not importable). Change both or neither; drift only misreports remaining quota.
- Hardcoded `/tmp` roots with **no env override**: `data_pipeline.UPLOAD_ROOT = /tmp/cds-uploads` (`mkdir` executed at import time) and `dev_sandbox._DATA_LOAD_ROOT`. `training._TRAINING_OUTPUT_ROOT` (honors `CDS_TRAINING_OUTPUT_DIR`) is the pattern to copy.
- `kms.py:428` — `app/schemas/kms.py` field names are a cross-language contract with `cds-volume-plugin/kms.go`; `kms.py:94` — reuse `sandbox_tasks.py`'s body-key merge rule, "do not invent a third"; `kms.py:314` — rotating to N+1 must not crypto-erase version N, and dependent-session termination runs BEFORE key mutation.
- `admin.py` uses raw Jinja2 + `HTMLResponse` on purpose (Starlette TemplateResponse breaks on Python 3.14+); the pages have no auth — leave `ADMIN_PAGES_ENABLED` off. They are dead weight for the product but **not deletable**: `tests/test_ocr_a137_admin_css.py`, `test_admin_xss_escaping.py` (asserts `function esc(` appears exactly once repo-wide), `test_ocr_a241/a242_*`, `test_ocr_a287_*`, `test_ocr_a115_*` parse the templates and `app/static`.
