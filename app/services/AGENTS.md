## CONVENTIONS
- Import the module-level singleton at file tail (`xxx = XxxService()`) or the factory (`k8s_sandbox.get_k8s_adapter()`) — no DI container, no FastAPI `Depends` for services.
- Lazy in-function imports are the norm (break cycles with torch, redis, kubernetes, Cryptodome). Keep new heavy imports lazy.
- Fail-closed + honest degradation: unsupported input returns `SECURITY ERROR: ...`; simulations expose `is_simulation`/`backend` flags and `main.py` surfaces every enabled fallback at boot (T12) — no silent degradation.
- Envelope layout `[nonce(12)][tag(16)][ciphertext]` (SM4-GCM via `app/utils/crypto.SM4Cipher`) is canonical for workspace/session-file/DB-file encryption. `storage_service._pack_envelope` is deliberately DIFFERENT: `!BI` header `version|key_id_len|key_id` ahead of the same three fields, version-checked on unpack — don't cross-mix the two readers.
- State machines are module-level `dict[state, set[state]]` + `ACTIVE_STATES`/`TERMINAL_STATES`, terminal = zero outgoing edges (`session_state_machine`, `task_state_machine`); only the task variant also transitions and reports progress.
- Session/DEK keys travel only via env vars (`CDS_SESSION_KEY`, `CDS_DEK_HEX`); never written to disk (KMS enforces).
- Container-ID prefix selects the adapter: `l0-`, `tee-`, `fc-`, `bwrap-`, `k8s-`, `l2c-`. Workspaces: `/tmp/cds-sandbox*/{user_id}/{session_id}/{input,output,tmp}`. Per SS-13 an L2'/`l2c` request never degrades to process isolation — closed nodes or dataplane disabled returns `RUNTIME_UNAVAILABLE`.
- Sandbox-level capability claims come from `capability_matrix.get_capability_matrix()` only — never re-derive `real|simulated|unsupported|planned` at a call site.
- Sandbox-side programs ship as Python string literals executed in the sandbox. Runner templates (`rag_service`, `inference_service`, `agent_service`, `notebook_service`) are ast/byte-validated against the trusted template — change template and `validate_*_runner` together; the self-generated ones (`session_templates._PYTHON_ANALYSIS_MAIN`, `unstructured_pipeline._{ocr,asr,video,document,dicom,generic}_script`) are NOT validated, so never present the two as the same guarantee.
- Quotas: Redis Lua atomic scripts (`quota_manager`), in-memory fallback when Redis absent; tests use `fakeredis[lua]`.
- Validation errors raise `CDSError(code=...)` from `app.core.errors` — but only in part of this layer (see ANTI-PATTERNS): `cube_*`, `crypto_service`, `network_policy`, `policy_compiler`, `node_selector`, `workflow_service`, `delivery_service` comply; `cross_space_policy`/`federation_connector`/`data_processing` raise `ValueError`, `db_access_proxy` raises `PermissionError`, `crypto_service` also raises `RuntimeError`. `HTTPException` never appears here. Scanners and adapters return error-shaped results instead of throwing (`ScanResult`, `AnchorResult`, `SyncResult`).
- K8s dual path: typed `kubernetes` client when `K8S_USE_PYTHON_CLIENT`, else kubectl subprocess with a `__CDS_EXIT__:` stdout sentinel protocol. The whole k8s level is deprecated in favour of the Cube dataplane (SS-10 CB-01) — do not extend it.
- Not everything is GM crypto: `delivery_service.sign_payload` is HMAC-SHA256 (`X-Signature: t=…,v=…`, replay window ±300 s) while audit anchoring is SM3 — check the module before assuming 国密.
- Redis-free degradation is a pattern, not an accident: `quota_manager` (Lua `LUA_INCREMENT_AND_CHECK` → local counters), `task_queue` (`_memory_queue`), `task_worker` (`_execute_task_direct`), `sandbox_manager` quota cache — each logs once and keeps running single-process; the durable path is the DB table (W16).
- Handlers never commit — transaction ownership stays with the caller (`integrity_patrol` states the 铁律; violating it yields stale rows / `MissingGreenlet`). Audit writes go through `audit_service.log` only.
- Honesty surfaces go beyond `is_simulation`: tri-state `ok|missing|uncheckable` (`integrity_patrol`, `storage_service.stat_presence`) with `NULL` timestamps separating "never checked" from "checked, inconclusive", and named backends instead of claims (`tlcp_service._sm3_backend()` → `"sha256-fallback"`).

## ANTI-PATTERNS (THIS PROJECT)
- Simulation ladders are design, not bugs to delete: firecracker `firecracker > qemu-tcg > simulation` (simulation = plain subprocess, NO isolation), `tee_simulator` software attestation, `cpu_trainer._simulate_fallback` (fail-closed under `TRAINING_REQUIRE_TORCH`), `gpu_tee_runtime` stubs.
- ~~Known defect (S4)~~ CLOSED (PZ-04/MR-A13): `firecracker_runtime` now mirrors `sandbox_runtime._seccomp_fallback_allowed`, so the seccomp-less retry is gated by `SECCOMP_FALLBACK_ALLOWED` everywhere and fails honestly when denied.
- Two SM3 paths in `crypto_service`: `sm3_hash` honours `SM3_FALLBACK_ALLOWED`, but the internal `_sm3_hash_with_z`/`sm2_sign` use gmssl directly and only raise `RuntimeError` when gmssl is absent — that path has no GM/T-claim gate.
- `gateway_service.py:82 sm3_hash` is the ONLY SM3 copy in the repo with an UNGATED `ImportError → SHA-256` fallback (no `SM3_FALLBACK_ALLOWED`, no disclosure). SM3 hashing exists 5× (`utils/crypto`, `crypto_service`, `gateway_service`, `secure_duckdb`, `merkle_service`) — reach for `crypto_service.sm3_hash`; never add a 6th, and never route a new anchored value through the gateway copy.
- Duplicated logic to consolidate, not copy: bwrap arg construction (4 copies — `sandbox_security.build_bwrap_args`, `sandbox_runtime._build_l0_bwrap_args`, `firecracker_runtime._build_sim_bwrap_args`, the inline argv in `tee_simulator`), SM3 (5×), X.509/PEM building (3), gmssl ImportError guards (3), ClickHouse URL parsing (`audit_service` + `gateway_service`), CN PII regex tables (`training_pipeline`, `test_data_generator` beside `pii_ner`/`streaming_inspector`), and two parallel vision stacks (`vision_pipeline` / `vision_multimodal_runtime` redefine `SecureImageDataLoader`, the 6-model `ALLOWED_MULTIMODAL_MODELS` literal and redaction steps, but disclose simulation by DIFFERENT mechanisms — metadata key vs byte suffix).
- Same-name-different-class traps: `PolicyEvaluator` (`policy_compiler.py:475` local stub vs `policy_evaluator.py:73` the real DB+OPA PDP), `MIAProbe` (`mia_probe.py:55` vs `llm_sft_runtime.py:274`), `AttestationStatus` (`remote_attestation.py:66` vs `result_verifier.py:34`).
- No production importer — verify before "fixing", extend only with the user's go-ahead: `proxy_launcher` (0 refs), `stream_audit`, `task_scheduler`, `task_circuit_breaker`, `scenario_engine`, `pg_rls_manager` (687 L, the dead half of the RLS twin), `query_rewriter`, `result_verifier`, `audit_partition`, `field_acl`, `k_anonymity`, `memorization_check`, `vision_pipeline`, `vision_multimodal_runtime`, `training_pipeline`, `training_audit`, `training_config_validator`. (`rls_engine.py:17`'s A133 note claiming `pg_rls_manager` has zero importers "even in tests" is itself stale — `tests/test_a133_rls_twin_fixes.py` imports it.)
- `code_scanner`'s import whitelist is NOT a security boundary (A98): it already admits file-I/O and external-source libs (`pathlib`, `pyarrow`, `PIL`, `cv2`, `duckdb`, `sqlalchemy`) and discloses those as WARNING, never FATAL. The real boundary is the hypervisor mount set (bwrap/Cube) + `cube_runtime_adapter.HARVEST_DIRS`; `SANDBOX_OUTPUT_PATHS` must stay same-source with `HARVEST_DIRS`. `agent_service`/`agent_tools` 铁律: the whitelist is NEVER widened and users never supply tool code.
- `retention_janitor`: `REAL_DELETE_WHITELIST` = exactly `{alert_records, session_workspace_residue, dev_debug_artifacts}`, `NEVER_DELETE_CATEGORIES` = `{audit_logs, merkle_leaves, delivery_bundles, data_resources}` — audit logs and Merkle leaves are NEVER purged (retention 0 = keep forever), `_FS_ROOTS` is hardcoded on purpose (configurable roots = delete-any-directory-by-config). Config may only NARROW the whitelist; `_require_deletable` runs before any SELECT/DELETE; `RETENTION_JANITOR_DRY_RUN=True` by default and the cycle needs BOTH `JANITOR_ENABLED` and `RETENTION_JANITOR_ENABLED`.
- seccomp discipline: the BPF fd is one-per-exec and must be returned via `_release_seccomp_fd` (a shared fd makes prior bwrap reads hit EOF → every later `PR_SET_SECCOMP` returns EINVAL); the seccomp-less retry is gated by `SECCOMP_FALLBACK_ALLOWED` in both `sandbox_runtime` and `firecracker_runtime` and fails closed when false.
- Frozen wire formats have pin tests; changing them re-anchors history: `merkle_service.merkle_leaf_preimage` = `id|action|resource_type|resource_id|ts` (`|`, `\`-escape, escape-before-separator) — "Do NOT improve it; fix ambiguity on the write side"; `audit_service` SM2-signed events; `kms_service` key blob / DEK-wrapped shapes.
- `vision_pipeline`/`vision_multimodal_runtime` training is a deterministic hash-seeded loop, NOT torch; `model_watermark` is a seeded-PRNG scheme. Tests pin these behaviors.
